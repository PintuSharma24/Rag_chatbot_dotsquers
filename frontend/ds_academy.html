DS Academy · AI chatbot system design

How the DS Academy chatbot gets built, end to end

A retrieval-based AI assistant for Dotsquares Academy — architecture, build workflow, fallback logic, and the feedback loop that keeps it improving.

FastAPI PostgreSQL + pgvector Ollama (local LLM) Docker HTML / CSS / JS
Architecture

Four layers, one request path

A student's message travels down through these layers and the answer travels back up the same path.

Client layer

What students and staff actually see
Chat widget — public, embedded on the site Admin panel — staff-only, separate login

API layer — FastAPI

Routes requests to the right service
Auth service Chat service — RAG orchestration Admin service — content CRUD

AI processing layer

The only layer that reasons over text
Embedding service — sentence-transformers LLM service — local Ollama, cloud fallback

Data layer

One PostgreSQL database, pgvector included
content_chunks chat_logs admins, chat_sessions
Build workflow

Where the data comes from, and what AI actually does

Most of this is code you write by hand. AI only does two jobs: turning text into vectors, and turning retrieved context into an answer.

Fallback and guardrails

What happens when the bot doesn't know

The bot never guesses. If nothing relevant is found, it says so instead of inventing an answer.
